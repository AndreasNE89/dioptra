Dioptra — Support

A file manager for people who want to see what is actually on their disk

Questions, bugs, and requests: hakka_kanon@live.no
Please include your macOS version, your Dioptra version (Dioptra ▸ About Dioptra), and what you were doing at the time.

Known issues in versions 1.0 and 1.1

Two problems in these versions can remove files you meant to keep. Fixes for both are planned for version 1.2. Until you have it:

  • Don't press ⌘Z or ⌘⌫ while typing in a field. In a rename field, the address bar or the search field, ⌘Z undoes your last file operation instead of your typing (a move is reversed, or a folder you just made goes to the Trash), and ⌘⌫ moves the selected files to the Trash. Press Esc to leave a rename field, or click in the file list, before you press ⌘Z. To clear text, use ⌫.
  • Check every Reclaim Space item before you trash it, including the ones Select Safe Items ticks. Reclaim can suggest files it should leave alone: duplicates inside a project's .git folder, a “kept” copy that is itself in the Trash, and iPhone backups and other data in your Library folder. Reclaim scans the folder you are browsing, so run it on one such as Downloads rather than on your whole home folder, which is the scan that reaches the Trash and Library. Untick anything in .git, the Trash or Library, and anything you don't recognise. Each item shows only one folder, even when its files are in several, so if you can't tell where an item's files are, leave it unticked. Reclaim moves files to the Trash rather than deleting them, so look there before you empty it.

Requirements

Dioptra runs on macOS 26 or later. Organize, and the short written summary in Reclaim Space, need Apple Intelligence, on a Mac that supports it and with it turned on in System Settings. Everything else works without it.

Dioptra is on the Mac App Store, where the version history lists what changed in each release. To see which version you have, choose Dioptra ▸ About Dioptra.

Questions that come up first

Dioptra is empty when I open it. Is it broken?

No — that is by design. Dioptra is sandboxed and begins with access to nothing at all. On first launch it asks for a folder: Grant Access to Your Home Folder and Choose a Different Folder… both open the standard macOS folder picker, and whatever folder you choose there becomes the part of your disk Dioptra can read. It is remembered the next time you launch. If you chose Skip for Now, or want more, use Add Location… in the sidebar; Settings ▸ Locations lists what you have granted and removes it just as easily.

This is deliberate. A file manager that quietly helped itself to your whole home directory would be easier to write and much harder to trust.

Why can't it open some folder I picked a while ago?

Dioptra remembers each folder you grant as a macOS bookmark. The bookmark follows the folder if you rename it or move it elsewhere on the same disk, and Dioptra picks up the new place the next time it launches. It stops working when:

  • The disk or server is not connected. Nothing is lost: connect it again. If the folder still shows as locked or not granted, quit and reopen Dioptra with the disk connected. There is no need to grant it again.
  • The folder was deleted or moved to another disk, or the disk was erased or replaced. The saved permission no longer points anywhere. Grant the folder again with Add Location… in the sidebar, or Grant Again… in Settings ▸ Locations.

Folder sizes show “—” instead of a number.

What the Size column shows for a folder depends on Settings ▸ General ▸ Folder sizes:

  • When I ask, the default: every folder shows “—” until you right-click it and choose Calculate Size, which measures the whole folder.
  • Automatically: folders are measured as they come into view, but Dioptra gives up on very large ones rather than freezing while it counts. Those show “—” until you choose Calculate Size.
  • Never: folders always show “—”, and Calculate Size is not offered.

In every mode, Space view maps the whole folder as rectangles sized by what they actually use.

The folder tree shows “N more items…”.

The navigation tree draws at most 400 items per folder so it stays responsive. When there are more, it says how many it left out rather than silently hiding them, and clicking that row opens the folder in the main list, which has no limit.

Can I drag photos from Photos, or attachments from Mail?

Those apps hand over a promise of a file rather than a file. Version 1.1 and later accept promised files: drop a photo from Photos or an attachment from Mail on the file list, and it lands in the folder you are browsing, with a progress ticket and undo like any other copy. Version 1.0 does not accept them, and the drop does nothing. In 1.0, drag from Finder instead, or export first: choose File ▸ Export in Photos, or save the attachment in Mail, then drag the saved file in. Dragging from Finder, or from any app that provides a real file, works in every version.

Some shortcuts worth knowing

  • ⌘⇧P — jump to any folder by typing part of its name
  • ⌘⇧\ — split the tab into two panes
  • ⌥⇥ — move focus to the other pane
  • F2 — rename; with several files selected, batch rename. On most Mac keyboards, hold Fn and press F2, or choose File ▸ Rename.
  • ↩ — open the selection; with several files selected, every one of them opens
  • ⌘Z — undo the last file operation, including moves and Move to Trash. Delete Permanently cannot be undone. In 1.0 and 1.1, leave any text field first (see known issues).

Refunds and removal

Can I have a refund?

Refunds are Apple's to give rather than ours. Every App Store purchase goes through Apple, so we never see your payment details and have no way to look up what you bought. Ask at reportaproblem.apple.com.

How do I remove Dioptra completely?

Drag the app to the Trash. That removes the app but not the container macOS keeps for it: deleting a sandboxed app leaves its container behind. It is the folder ~/Library/Containers/App.andreas.Filefy (the identifier dates from before the app was called Dioptra; Finder may list the folder as Dioptra). Deleting that folder removes everything the app ever stored — including the security-scoped bookmarks recording which folders you granted access to. That is the whole of it. There is no copy anywhere else, because nothing was ever sent anywhere else.
